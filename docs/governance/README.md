# Cross-project engineering governance

These documents are written for reuse across software projects. When adopting one, record its version and a commit-pinned GitHub link in the project's governing references.

| Document | Status |
| --- | --- |
| [AI-Assisted Software Engineering Governance Standard v1.0](AI_Assisted_Software_Engineering_Governance_Standard_v1_0.odt) | Original November 4, 2026 ODT, preserved byte for byte. |
| [AI-Assisted Software Engineering Governance Standard v1.1 draft](AI_Assisted_Software_Engineering_Governance_Standard_v1_1_DRAFT.odt) | Targeted proposed update for owner review. Version 1.0 continues to govern where adopted. |
| [Software Development Roadmap Planning and Execution Guide v1.0](Software_Development_Roadmap_Planning_and_Execution_Guide_v1_0.odt) | Original draft companion guide, preserved byte for byte. It provides planning guidance under the governing standard and project approvals. |
| [Software Development Roadmap Planning and Execution Guide v1.1 draft](Software_Development_Roadmap_Planning_and_Execution_Guide_v1_1_DRAFT.odt) | Targeted proposed update for owner review. |

The Standard v1.1 draft clarifies delegated authority and technical permissions, installer and runtime privileges, private-use evidence and redistribution, repository review and release states, durable source references, operational witness boundaries, and the role of alignment ratings in conformance review. Section numbering, source attribution and the original text outside those additions are preserved.

The Roadmap Guide v1.1 draft clarifies access blockers, installation-first FAT readiness, installation and recovery evidence, impact-based integration retesting, periodic alignment reviews, and handoff recovery after a branch change. It keeps Governance Standard v1.0 as its governing reference and preserves the existing project approval and acceptance boundaries.
